## v0 → v1: 구조 분리와 확장성 개선

### 브로드캐스트 O(N²) 제거

원본은 이동 패킷마다 접속자 전체를 순회했다.

```cpp
for (auto& [key, pl] : clients)
    if (pl && pl->m_id != self->m_id && pl->m_state == CS_PLAYING)
        snapshot.push_back(pl);
```

이동은 초당 수십 번 일어나므로 O(N²)다. `MAX_PLAYERS`가 10000인데
동접 100명만 돼도 무너진다.

월드를 128m 섹터로 나누고 주변 3×3만 순회하도록 바꿨다.
`VIEW_RANGE <= SECTOR_SIZE` 불변식이 이 최적화의 정당성을 보장한다.

### 패킷당 힙 할당 제거

원본은 recv 완료마다 `std::vector`를 새로 만들어 복사하고,
send는 생성자와 `connect()`에서 각각 한 번씩 복사했다.
패킷 하나당 최소 2회 할당이다.

호출자가 버퍼를 소유하고 sender는 포인터만 받도록 바꿔 할당을 없앴다.
전송은 대기 버퍼에 이어붙였다가 한 번의 `WSASend`로 합쳐 내보낸다.

### 정확성 문제

| 문제 | 증상 |
|---|---|
| `unsafe_erase` | 순회 중 삭제하면 미정의 동작. 스트레스 테스트에서만 간헐적으로 터진다 |
| `clients[id]` | 없는 키 조회 시 nullptr 원소를 삽입. 나간 플레이어를 조회할 때마다 맵이 커진다 |
| `size` 오프바이원 | 필드는 255 상한인데 `static_assert(<=256)`. 256바이트 패킷이 통과하면 스트림 전체가 버려진다 |
| `short` 좌표 캐스팅 | 원점에서 327m를 넘으면 좌표가 뒤집힌다. 오픈월드에서 치명적 |
| enum을 패킷에 직접 | 크기가 구현체 정의. 서버/클라 컴파일러가 다르면 조용히 깨진다 |
| 구조체 미초기화 | `S2C_AddObject packet;` — 스택 쓰레기값이 네트워크로 나간다 |
| NPC가 SESSION | 플레이어 슬롯을 잠식. `MAX_PLAYERS` 검사에 NPC가 포함됐다 |

## v1 → v2: 서버 권위 이동

```
[v1]  클라: "나 (500, 300)에 있어"  →  서버: 받아 적음
[v2]  클라: "앞으로 가고 싶어"      →  서버: 시뮬레이션 → "너 (498, 302)야"
```

`HandleMove`가 `HandleInput`이 되면서 위치 계산이 패킷 핸들러에서
완전히 사라졌다. 30Hz 고정 틱 루프가 새로 생겼다.

### 시야 상한의 효과

밀집 시나리오(반경 200m에 800명) 기준 추정값이다.

| 구성 | 추정 대역폭 |
|---|---|
| v1 (상한 없음, 30Hz) | 약 460 MB/s |
| v2 (상한 50, 15Hz) | 약 19 MB/s |
| v2 + 거리 티어 + 움직인 것만 | 그보다 더 낮음 |

실측이 아니라 계산값이다. 실제 수치는 부하 테스트로 확인해야 한다.

### 시야 목록 소유권 변경

v1에서는 내가 누군가를 발견하면 상대의 시야 목록에도 나를 밀어넣었다.
두 가지 문제가 있었다. 상대의 시야 상한을 넘길 수 있고,
세션 간 교차 변경이라 병렬화가 막힌다.

각자 자기 시야만 계산하도록 바꿨다. 상대는 자기 차례(최대 100ms 뒤)에
나를 발견한다. 부수 효과로 접속 종료 시 REMOVE 브로드캐스트가
통째로 사라졌다. 그리드에서 빠지면 다음 계산에서 자동으로 이탈 처리된다.

### 락 획득 횟수

동접 3000, 시야 50 기준.

| | 락 획득 / 틱 |
|---|---|
| 패킷마다 `SendPacket` | 150,000 |
| 배치 `FlushSendBatch` | 3,000 |

## v2 → v3: 전투와 AI

새로 생긴 것은 대부분 추가 파일이라 기존 코드 변경은 작다.

| 추가 | 내용 |
|---|---|
| `skill_table.h`, `skills.csv` | 스킬 수치. 클라와 공유 |
| `combat.h`, `combat_tick.h` | 부채꼴/원 판정, 윈드업 예약, 투사체 |
| `fixed_math.h` | 판정용 삼각함수 테이블 |
| `monster_table.h`, `monsters.csv` | 몬스터 수치. `aggressive` 플래그 |
| `monster_ai.h` | 상태 기계, 리쉬, 섹터 휴면 |
| `pathfinding.h` | 시선 검사 + 지역 A* |

기존 코드 변경은 `m_moved`를 전역 `g_moved`로 뺀 것 하나다.
AI도 몬스터를 움직이므로 양쪽이 같은 집합에 기록해야 한다.

## 커밋 히스토리에 대한 주의

`v0-original`과 `v1-refactor`는 실제 작업 시점의 스냅샷이다.
`v2-authority`는 최종본에서 전투/AI 부분을 제거해 재구성한 것이라
그 시점의 실제 코드와 완전히 같지는 않다.
파일 단위 변화와 설계 흐름을 보는 용도로 쓰기 바란다.
